# Supply-chain risk note — `claims-system` server

1. **Who wrote it:** in this repo it's `app/mcp_servers/claims_system_server.py`, written by us as a stand-in for the claims-platform team's real server (per the task, treat it as *their* code, run on *their* infrastructure, reached over stdio/HTTP with no code review on our side).
2. **What it can reach:** it reads one local JSON file (`analysis/week9/claims_system_data.json`) and returns claim status and adjuster-note history for whatever `claim_number` it's given — in a real deployment this token would sit against their production claims database, which is a much bigger reach than our own `policy-tools` server (that one only touches our local policy-doc index and the Week 7/8 synthetic claim records).
3. **What it logs:** unknown from our side — a third-party server we didn't write can log every claim number we send it, our client identity, and our IP, with no way for us to audit or disable it; it runs inside our agent's trust boundary the moment it's added to `mcp_config.json`.
4. **What a stolen token could do:** read adjuster-note history (often free-text, sometimes sensitive: DUI findings, burglary suspicion, medical/personal detail in notes) for every claim number an attacker chooses to enumerate — this is a read-heavy, high-blast-radius capability for a single leaked credential, and neither of its two tools requires anything beyond a claim number to use.
5. **Ship or don't:** ship it scoped, not as-is — pair it with a token limited to these two read-only tools (never anything that writes or settles), rate-limit or log every `claim_number` argument on our side regardless of their logging, and treat `get_adjuster_note_history` as the higher-risk tool of the two, per the bonus gateway's scoped-denial design.
